# score-audit

**How much of a benchmark score is real?** Three small, reproducible audits of design choices that quietly change
what a score means: adversarial item filtering, all-or-nothing composite scoring, and LLM judges that call an
answer "incorrect" without showing what is false.

Every number below is regenerated by the scripts in `experiments/`. Experiments 1 and 2 are known-answer
simulations; experiment 3 uses real model outputs on TruthfulQA, cached in `data/llm_cache.jsonl` so it re-runs
offline with no API key.

## Findings

### 1. Adversarial filtering penalises the systems used to build the benchmark
Items are kept only if none of five "filter" systems could solve them reliably. Each filter system has a twin of
identical ability that was not used for filtering.

![fig1](figures/fig1_filtering.png)

- With a moderate system-by-item interaction (sd = 1.0), a filter system scores **3.7 points below its twin** on
  average (200 seeds), and is below its twin in 90% of cases. At sd = 1.5 the gap is 7.6 points.
- **Inert control:** with no interaction (sd = 0) the gap is 0.0 points (95% range of single gaps: -4.2 to +4.0),
  so the penalty comes from selecting on each filter system's own weak spots, not from the simulation itself.

![fig1b](figures/fig1b_interaction_dose.png)

*Implication:* on an adversarially filtered benchmark, the systems used during construction are under-ranked
relative to equally capable newcomers. Report which systems were used for filtering, and compare them only with
caution.

### 2. All-or-nothing composites hide real differences
If a problem counts only when all three subtasks pass, the score is the cube of the per-subtask rate.

![fig2](figures/fig2_composite_floor.png)

- A **2% headline score is compatible with about 27% per-subtask success**.
- For two systems with a real 5-point per-subtask gap (40% vs 35%), 400 problems detect the better system
  **27% of the time with all-or-nothing scoring vs 70% with partial credit**. All-or-nothing needs about four
  times as many problems for the same power.

![fig2b](figures/fig2b_power.png)

*Implication:* report per-subtask (partial) credit alongside the strict score, especially near the floor.

### 3. Do LLM judges show what is false when they say "incorrect"?
Three systems answered 150 TruthfulQA questions. Two judges (GPT-4o-mini, Gemini-2.5-Flash-Lite) graded every
answer under an **evidence protocol**:
- the judge must quote the false sentence verbatim;
- code checks that the quote is really in the answer;
- a second, narrow call checks that the quoted claim contradicts the reference.

![fig3](figures/fig3_evidence.png)

- Of 321 "incorrect" verdicts, **203 (63%) passed the evidence check**. In 32 the quoted "false claim" did not
  appear in the answer at all; in 86 the quoted claim was judged not false.
- To test the check itself, a stronger model from a third family (Claude Haiku 4.5) labelled every "incorrect"
  verdict. It confirmed a false claim in **82.6% of raw verdicts and 90.6% of evidence-backed verdicts**.
  So the protocol raises precision, **but it also discards real errors**: 67-72% of the downgraded verdicts still
  contained a false claim. The weak link is the narrow claim check run by a small model.

![fig3c](figures/fig3c_adjudication.png)

- Agreement between the two judges (Cohen's kappa) was 0.63 on raw verdicts and 0.58 after the evidence check.

*Implication:* a verbatim-evidence requirement is a cheap way to find unsupported "incorrect" verdicts and to send
them for review. With a small verifier, it should flag verdicts, not overturn them automatically.

## Limitations
- Experiments 1 and 2 are simulations: they show the size and direction of an effect under stated assumptions,
  not its size on any particular benchmark.
- In experiment 3 the adjudicator is also a model, not a human; its labels estimate agreement with a stronger
  reader, not ground truth. A small human-labelled sample is the next step.
- TruthfulQA is short-form and adversarial; one judge (Gemini-2.5-Flash-Lite) also graded its own family's answers.
- One run per configuration at temperature 0.

## Reproduce
```bash
uv sync
uv run pytest -q                                        # 9 tests, no API calls
uv run python experiments/exp1_adversarial_filtering.py  # about 1 min
uv run python experiments/exp2_all_or_nothing.py         # about 1 min
uv run python experiments/exp3_evidence_backed_judging.py  # offline from data/llm_cache.jsonl
uv run python experiments/exp3b_adjudication.py
```
New API calls (only for uncached prompts) use `OPENROUTER_API_KEY`. On Windows, set `PYTHONUTF8=1`.
